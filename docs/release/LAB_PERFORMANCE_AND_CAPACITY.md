# 实验室性能与容量流程

## 可重复本地检查

在已构建的候选版本上执行：

```sh
SITE_URL=https://<authorized-lab-origin> INDEXING_ENABLED=false npm run release:lab
```

该流程启动本地生产服务器，记录首页可用前的冷启动时间、首页／搜索／ZCTA／州／比较页的稳态响应、2／4／8 并发 ZCTA 请求、5xx（服务器错误）计数及可用时的服务器 RSS（常驻内存）。结果写入 `test-results/release-lab.json`。

## 容量决策边界

| 级别 | 用途 | 发布前要求 |
| --- | --- | --- |
| 最低验证目标 | 1 vCPU / 2 GiB 内存 | 在真实候选托管环境完成启动、代表路线、短时并发与错误日志检查。 |
| 建议目标 | 2 vCPU / 4 GiB 内存或等效无服务器资源 | 作为首版预发布的起点，依据真实内存、延迟与错误数据调整。 |

本地结果只用于发现回归和提供托管验证脚本，不能外推为生产容量承诺。发布前仍需在被选择的托管平台记录冷启动、稳态内存、请求延迟、5xx（服务器错误）、崩溃与内存耗尽风险。
