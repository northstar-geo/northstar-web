# NorthStar Development Workflow

## Purpose

This document defines the standard workflow for developing the NorthStar Platform.

Every contributor, whether human or AI, should follow this workflow.

---

# Development Cycle

Every development task follows the same lifecycle.

Idea

↓

Planning

↓

Documentation

↓

Implementation

↓

Testing

↓

Git Commit

↓

Journal Update

↓

Project State Update

↓

Review

↓

Next Sprint

---

# Before Coding

Before implementing a feature:

- Understand the business purpose.
- Review related documentation.
- Confirm architecture consistency.
- Check existing components.
- Avoid duplicate implementations.

Documentation comes before implementation whenever possible.

---

# During Development

Every implementation should follow:

- Clean code
- Reusable components
- Consistent naming
- API-first thinking
- Mobile compatibility
- SEO awareness

---

# After Development

Every completed task should include:

- Git Commit
- Journal Update
- CHANGELOG update (if applicable)
- Decision Log update (if architecture changed)
- PROJECT_STATE update
- Sprint progress update

Code is never considered complete until documentation is updated.

---

# Sprint Completion

Every Sprint should produce:

- Working code
- Updated documentation
- Git history
- Sprint summary
- Lessons learned
- Next Sprint planning

---

# Knowledge Preservation

NorthStar should never depend on:

- Human memory
- AI conversation history
- Individual developers

The Git repository is the single source of truth.

Everything important must exist inside the repository.

---

# Continuous Improvement

Every Sprint should improve at least one of the following:

- Product quality
- Code quality
- Documentation
- User experience
- Architecture
- Automation
- Business value

---

# Final Rule

Build software that future developers will enjoy maintaining.

Leave the project better than you found it.
