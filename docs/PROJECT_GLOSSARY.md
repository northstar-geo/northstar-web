# NorthStar Project Glossary

## Purpose

This glossary defines the official terminology used throughout the NorthStar Platform.

Every contributor, whether human or AI, should use these terms consistently.

Consistent terminology improves communication, documentation quality, and long-term maintainability.

---

# Core Platform

## NorthStar

The overall technology platform.

NorthStar is the company-level platform that contains all products, services, APIs, and future business capabilities.

---

## Zipora

The first public product built on the NorthStar Platform.

Zipora focuses on ZIP Code, address, city, county, and location intelligence services.

---

## Platform

A collection of shared technologies, infrastructure, and services used by multiple products.

Examples include:

- Authentication
- Database
- APIs
- AI Services
- Deployment Pipeline

---

## Product

A user-facing application built on the NorthStar Platform.

Examples:

- Zipora Web
- Zipora Mobile
- Future Products

---

# Engineering

## Sprint

A short development cycle with defined goals and deliverables.

Each Sprint should end with working software and updated documentation.

---

## Milestone

A major project achievement.

Examples:

- First Public Release
- API Launch
- Mobile Release

---

## Feature

A user-visible capability.

Examples:

- ZIP Search
- City Search
- Favorites
- AI Assistant

---

## Module

A logical grouping of related functionality.

Examples:

- Search Module
- User Module
- Payment Module

---

## Component

A reusable UI element.

Examples:

- Button
- SearchBox
- Card
- Header
- Footer

---

## Service

A reusable business logic layer.

Examples:

- Search Service
- Location Service
- User Service

---

## API

Application Programming Interface.

Provides reusable functionality for:

- Web
- Mobile
- Enterprise
- AI

---

# Documentation

## Journal

Daily development log.

Records work completed each day.

---

## Review

Periodic project summary.

Types include:

- Weekly Review
- Monthly Review
- Yearly Review

---

## Changelog

A chronological record of significant project changes.

---

## Decision Log

Records major architectural, technical, business, and product decisions.

Explains not only what changed, but why.

---

## Project State

A snapshot of the project's current status.

Includes:

- Current Sprint
- Current Tasks
- Next Steps
- Known Risks

---

## AI Context

The primary onboarding document for AI assistants.

Designed to allow any AI to quickly understand the project.

---

# Product Strategy

## Documentation First

Documentation is created before or alongside implementation.

Documentation is considered part of the product.

---

## Platform First

Design reusable systems before building individual products.

---

## API First

Business logic should be reusable through APIs whenever practical.

---

## AI First

AI capabilities should be integrated throughout the platform where they improve user value.

---

## SEO First

Public pages should prioritize discoverability, accessibility, and search engine optimization.

---

## Mobile Ready

Features should be designed with future mobile applications in mind.

---

## Clean Architecture

Business logic should remain independent from frameworks and infrastructure.

---

# Business

## MVP

Minimum Viable Product.

The smallest useful version that can be released to real users.

---

## Monetization

Methods used to generate revenue.

Examples:

- Advertising
- Premium Membership
- API Subscription
- Enterprise Services
- Affiliate Marketing
- AI Services

---

## Enterprise

Business customers requiring advanced capabilities, APIs, or custom solutions.

---

## Developer Platform

A collection of APIs, SDKs, documentation, and tools for third-party developers.

---

## Crypto Integration

Support for cryptocurrency-related capabilities.

Examples:

- Bitcoin Payments
- Ethereum Payments
- Solana Payments
- Wallet Authentication

Crypto is considered an optional platform capability rather than the core business.

---

# Development Workflow

## Backlog

A prioritized list of planned work.

Items move from Backlog into future Sprints.

---

## Task

A specific unit of work completed during a Sprint.

---

## Pull Request (PR)

A proposed set of changes submitted for review before merging into another branch.

---

## Commit

A saved snapshot of project changes.

Each commit should represent one meaningful unit of progress.

---

## Branch

An independent line of development.

Examples:

- main
- develop
- feature/*
- hotfix/*

---

# Future Terms

This glossary should continue growing as the NorthStar Platform evolves.

Whenever a new technical or business concept becomes important, it should be defined here before becoming part of the project's standard terminology.
